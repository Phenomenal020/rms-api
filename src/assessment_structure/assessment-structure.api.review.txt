EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
The assessment-structure module configures per-term assessment components (type,
percentage, displayOrder) with POST (first save), GET (by termId), and PATCH
(full sync with diff). It uses OrgAdminGuard, requireTermInOrganization, DTO +
validateAssessmentEntries (100% total, unique types/orders), and runWithDbContext
on mutations. The PATCH diff (update/insert/delete) is sound and maps 23503 when
scores block deletion.

Main gaps: (1) success: string responses + ResponseTransform double-wrap; (2) GET
lacks runWithDbContext; (3) POST does not guard against existing structure (duplicate
POST → 409); (4) create insert is not transactional; (5) percentage uses @IsNumber
not @IsInt; (6) no @ArrayMaxSize on entries; (7) dead toDelete array in update;
(8) no LoggingInterceptor; (9) misleading comment "owner of the term" (uses org
membership). DB: assessment_structure CASCADE on term delete; assessment_score
RESTRICT blocks component delete when scores exist — correctly mapped.


1) MIDDLEWARE — How can it be used here? Is it being used correctly?
--------------------------------------------------------------------------------

Current state
  • App-wide requestId, requestLogger, helmet, 100 kb JSON limit. ✅
  • No module middleware — correct.

Recommendations
  A) App-wide middleware sufficient. ✅
  B) Optional rate limit on POST/PATCH (arrays of entries). 📌
  C) Consider slightly higher body limit only if many components — unlikely needed. ✅

What NOT to put in middleware
  • Term ownership — requireTermInOrganization in service.
  • 100% total validation — validateAssessmentEntries.


2) EXCEPTION FILTERS — General use and improvements
--------------------------------------------------------------------------------

  • getAssessmentStructure — no wrapper; generic 500 on DB failure.
  • validateAssessmentEntries failures → BadRequestException 400.

Mapped errors
  • 23505 → 409 duplicate type or displayOrder for term
  • 23503 → 400 cannot remove components with recorded scores ✅

Improvements

  B) success: true boolean responses. ✅

3) PIPES — General use and improvements
--------------------------------------------------------------------------------

Current usage
  • GetAssessmentStructureDto (termId query). ✅
  • CreateAssessmentStructureDto / UpdateAssessmentStructureDto with @ValidateNested. ✅
  • PatchAssessmentStructureParamsDto (termId param). ✅

Gaps

  A) @IsInt on percentage (medium)
     Schema integer; DTO uses @IsNumber — accepts 30.5 → DB may truncate or error.
     Use @IsInt @Min(1) @Max(100). ✅

  B) @MaxLength(16) on type (medium)
     Matches varchar(16) in schema. ✅

  C) @ArrayMaxSize on entries (medium)
     Unbounded array — large payload before validation. ✅

  D) UpdateAssessmentEntryDto.id — @IsOptional @IsUUID ✅ for new rows without id.

  E) POST termId in body + PATCH termId in URL — intentional; document that PATCH
     ignores body termId if ever added.
