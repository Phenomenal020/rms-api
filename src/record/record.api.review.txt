EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
The record module manages class-record export workflow: teachers submit snapshots
(student-view); org admins review via GET requests list, GET record JSON, PATCH
accept/reject.

Strengths: Mixed guard model (GET requests open to orgadmin + user; admin
mutations guarded); requireTermInOrganization with requireActive on list;
getRecord uses Drizzle relational query with org scope; accept/reject set
reviewedBy/reviewedAt; responses already use success: true.

Main gaps: (1) GET requests filter bug — eq(createdBy, formTeacherId) wrong for 
admin list + mislabels submitter as formTeacherName; (2) PENDING filter
commented out for orgadmin; (3) accept/reject do not require status PENDING;
(4) no runWithDbContext on any handler; (5) role check uses raw strings not
ROLE_* constants; (6) RejectRecordDto no @MaxLength(2000); (7) no
LoggingInterceptor; (8) getRecord only returns PENDING — cannot preview after
accept; (9) no UserGuard on GET requests (relies on service role string).

7) CODE QUALITY
--------------------------------------------------------------------------------

Strengths
  • requireTermInOrganization(..., { requireActive: true }) on list — aligns
    with export workflow during active term. ✅
  • getRecord org + requestId + PENDING guard. ✅
  • accept/reject null rejectionReason / set reviewed metadata. ✅

Issues

  A) requestFilters includes eq(createdBy, formTeacherId) (high) 📌
     Line compares export.createdBy to organisationClass.formTeacherId.
     Effect: only rows where submitter equals current form teacher — redundant
     if always true, breaks if form teacher changed after submit. Admin list
     should filter org + termId + status PENDING only.

  B) PENDING filter commented for orgadmin (high✅
     // requestFilters.push(eq(status, 'PENDING'));
     Admins may see ACCEPTED/REJECTED in "pending requests" UI.

  C) accept/reject: no status guard (high)
     Can re-accept or re-reject already reviewed requests.
     FIX: Request status already in place ✅

  D) formTeacherName mislabel (medium) 📌
     Join user on createdBy → rename submitterName or join form teacher separately.

  E) getRecord hard-coded PENDING only (medium) 📌
     Admin may need to view snapshot after accept for audit.

  F) No runWithDbContext (medium) ✅

  G) Role string literals 'orgadmin'/'user' (low) ✅

  H) accept/reject not transactional with validation (low)
     Single UPDATE — OK for now. ✅

  I) No LoggingInterceptor (low) ✅
