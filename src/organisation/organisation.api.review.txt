EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
The organisation module exposes two org-admin endpoints: GET dashboard stats
(enrolled students, subjects, pending/accepted record-export counts) and POST
add-member (resolve email → userId → Better Auth organisation.addMember).

Strengths: OrgAdminGuard on controller; dashboard uses requireOrganizationId and
parallel counts; dashboard already returns success: true.

Main gaps: (1) addMember does not receive admin userId — no org scoping before
BA call; (2) addMember returns success: string (double-wrap risk); (3) BA
addMember called without session/headers — may not attach member to caller's org;
(4) no runWithDbContext on either handler; (5) controller method misnamed
saveOrganisation; (6) POST returns 200 not 201; (7) no LoggingInterceptor;
(8) duplicate overlap with teacher-invitation module addMember.


1) MIDDLEWARE — How can it be used here? Is it being used correctly?
--------------------------------------------------------------------------------

Current state
  • App-wide requestId, requestLogger, helmet, 100 kb JSON limit. ✅
  • No module middleware — correct.

Recommendations
  A) App-wide middleware sufficient. ✅
  B) Optional rate limit on POST add-member (abuse: enumerate emails). 📌

What NOT to put in middleware
  • Email → user lookup — service concern.
  • Better Auth addMember — service with admin session context.


2) EXCEPTION FILTERS — General use and improvements
--------------------------------------------------------------------------------

Current usage
  • Neither handler uses runWithDbContext.
  • addMember catches unknown errors → generic BadRequestException.
  • getDashboard: DB errors → unhandled 500.

Mapped errors
  • No 'organisation' context in postgres-error.mapper.
  • addMember duplicate member likely surfaces as BA error → swallowed as 400.

Improvements
  A) runWithDbContext on getDashboard (generic or new 'organisation' context). ✅
  B) addMember: map BA conflict/duplicate to 409 with clear message. ✅
  C) Standardise addMember success: true (boolean). ✅
